# Upgrade Guide

This document describes the upgrade process between major versions.

The upgrade **must be executed step by step**. Versions must be migrated in order, starting from the oldest version and moving progressively to the latest version.

The required migration path is:

1. **v8.x → v9.0.0**
2. **v9.0.0 → v9.0.3**

> ⚠️ Do not skip versions. Skipping a migration step can leave the system with missing configurations, outdated database structures, or incompatible files.

---

# Migrate v9.0.0 to v9.0.3

## Overview

This release completes the migration from the v8.x structure.

The **v9.0.3** update includes:

- Removal of orphan files generated by the old **v8.x** structure.
- Addition of language support.
- Fixes for the module installation command.
- Cleanup of obsolete storage directories.

Before starting this upgrade, make sure you have a backup of any required custom data.

---

## 1. Backup sitemap indexation data

If your installation uses sitemap indexation, create a backup copy of the following file before stopping the containers:

```
/public/sitemaps/pages.xml
```

Save this file outside the container because the old sitemap volume will be removed during this migration.

---

## 2. Stop the Docker containers

Stop the current running environment:

```bash
docker compose -f docker-prod.yml down
```

---

## 3. Switch to version v9.0.3

Update your repository to the new version:

```bash
git checkout -b v9.0.3 v9.0.3
```

Verify that you are using the correct branch:

```bash
git branch
```

---

## 4. Update Docker volumes configuration

Open the Docker compose file:

```bash
vim docker-prod.yml
```

Remove the old volumes related to:

- Language files (`lang`)
- Sitemap files (`sitemaps`)

These volumes are no longer required in v9.0.3.

---

## 5. Deploy the new version

Start the containers using the new deployment script:

```bash
./production --deploy
```

Wait until all containers are running correctly before continuing.

---

## 6. Access the application container

Open a shell inside the container:

```bash
./production bash
```

---

## 7. Remove obsolete storage directories

Remove the old directories created by previous versions:

```bash
rm -rf storage/app/tmp
rm -rf storage/app/upload
rm -rf storage/app/backups
```

The migration to **v9.0.3** is now complete.

---

# Install Content Module

After upgrading to v9.0.3, install the **Content module** to enable SEO features.

The module is public and can be customized. You are free to modify it or add new functionality according to your project requirements.

Repository:

```
https://github.com/elyerrlabs/content.git
```

---

## Install the module

Run:

```bash
php artisan module:install
```

Follow the installation wizard:

### 1. Select the repository type

Use the arrow keys (`up` / `down`) and select:

```
git
```

Press **Enter**.

---

### 2. Enter the repository URL

Paste:

```
https://github.com/elyerrlabs/content.git
```

Press **Enter**.

---

### 3. Select the environment

Use the arrow keys and select:

```
production
```

---

### 4. Repository privacy

When asked if the repository is private, type:

```
no
```

---

### 5. Select module version

Select the latest available version.

Example:

```
v1.0.1
```

After completing these steps, the Content module will be installed and ready to use.

# Migrate v8.0.1 to v9.0.0

## Overview

This migration introduces the new v9 architecture.

The main changes include:

- New module migration system.
- Updated Docker deployment scripts.
- Removal of deprecated configurations.
- Migration of module settings into `modules.json`.
- Removal of deprecated services.

---

## 1. Retrieve the latest repository changes

Update your local repository:

```bash
git fetch
```

---

## 2. Stop Docker containers

Stop the current environment:

```bash
docker compose -f docker-compose-prod.yml down
```

---

## 3. Switch to version v9.0.0

Checkout the new version:

```bash
git checkout -b v9.0.0 v9.0.0
```

Verify the current branch:

```bash
git branch
```

---

## 4. Rename Docker compose files

The Docker compose files were renamed.

Rename them according to your environment:

```
docker-compose-dev.yml      → docker-dev.yml
docker-compose-staging.yml  → docker-staging.yml
docker-compose-prod.yml     → docker-prod.yml
```

---

## 5. Deploy the new version

Execute the deployment command depending on your environment.

### Development

```bash
./dev --deploy
```

### Staging

```bash
./staging --deploy
```

### Production

```bash
./production --deploy
```

---

## 6. Remove deprecated configuration keys

Remove old configuration values that are no longer used:

```bash
./production php artisan config:delete-key "core.partner"
./production php artisan config:delete-key "core.transaction"
./production php artisan config:delete-key "rate_limit.partner"
./production php artisan config:delete-key "rate_limit.ecommerce"
./production php artisan config:delete-key "module_enabled"
./production php artisan config:delete-key "billing"
./production php artisan config:delete-key "stripe"
```

---

## 7. Remove deprecated services

Run:

```bash
./production php artisan settings:drop-service
```

Use the arrow keys (`up` / `down`) to select the service group and then the service to remove.

Remove the following services:

### Administrator

- `refunds`
- `plan`
- `transactions`
- `partner`
- `ecommerce`

### Developers

- `pages`
- `seo`

### Reseller

- `partner`

---

## 8. Migrate module database configuration

Move module database configuration into the new `modules.json` structure:

```bash
./production php artisan module:migration
```

The command will generate the required migration script.

Review the generated changes and merge them before applying them.

---

# Deployment Script Changes

Starting from v9.0.0, deployment scripts were unified into a single command per environment.

The old scripts:

- `deploy-dev.sh`
- `deploy-staging.sh`
- `deploy-prod.sh`

were merged into:

- `dev`
- `staging`
- `production`
